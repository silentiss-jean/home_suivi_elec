Home Suivi Élec — Plan structuré et diagramme de flux

===========================================
PLAN ÉTAPE PAR ÉTAPE

Étape 0 — Détection complète des capteurs 
-------------------------------------------------
Objectif :
- Collecter tous les capteurs de puissance
- Stocker intégration, pièce, entity_id et unité

Actions :
1. Modifier run_detect_local :
   - Filtrer device_class = "power"
   - Ajouter intégration et pièce (friendly_name ou GA)
2. Sauvegarder dans capteurs_power.json
3. Ajouter logs détaillés pour vérification

Test :
- Lancer generate_local_data depuis HA
- Vérifier JSON et logs

-------------------------------------------------
Étape 1 — Référence et capteurs non mesurés
-------------------------------------------
Objectif :
- Comparer la somme des capteurs avec consommation globale (clé atom)
- Identifier ce qui n'est pas mesuré

Actions :
1. Ajouter capteur global atom
2. Créer capteurs_non_mesures.json avec :
   - Intégration / pièce
   - Capteurs manquants
3. Ajouter logs détaillés

Test :
- Vérifier rapport JSON
- Vérifier logs dans HA

-------------------------------------------------
Étape 2 — Sélection des capteurs à suivre
------------------------------------------
Objectif :
- Permettre sélection fine par intégration et pièce

Actions :
1. Fichier selected_sensors.json
   Exemple :
   {
     "zigbee": {
       "salon": ["sensor.salon_power"],
       "cuisine": []
     },
     "mqtt": {
       "logement": ["sensor.compteur_edf"]
     }
   }
2. Service HA select_sensors pour modifier la sélection
3. Logs pour valider la sélection

Test :
- Cocher/décocher capteurs → vérifier JSON et logs

-------------------------------------------------
Étape 3 — Génération du tableau de bord Lovelace
-----------------------------------------------
Objectif :
- Dashboard regroupé par intégration et pièce
- Afficher coût par capteur/pièce et total

Actions :
1. Service generate_lovelace_custom :
   - Lit selected_sensors.json
   - Organise cartes par intégration et pièce
   - Compare avec valeur atom
2. Types de cartes :
   - entities
   - glance
   - history_graph
3. Ajouter logs détaillés

Test :
- Lancer le service → vérifier dashboard

-------------------------------------------------
Étape 4 — Analyse du suivi et alertes
-------------------------------------
Objectif :
- Détecter capteurs non mesurés ou désactivés

Actions :
1. Comparer total capteurs sélectionnés vs total atom
2. Créer sensor.conso_non_mesuree
3. Logs pour alertes

Test :
- Vérifier que le sensor reflète bien les écarts

-------------------------------------------------
Étape 5 — ConfigFlow et OptionsFlow
-----------------------------------
Objectif :
- ConfigFlow : hub, type contrat, auto_generate_lovelace
- OptionsFlow : pour modification rapide des paramètres

Actions :
- Auto-génération Lovelace reste pour dashboard de base
- Sélection fine → service ou panneau custom, hors ConfigFlow

Test :
- Vérifier ConfigFlow complet et OptionsFlow (roue)

===========================================
DIAGRAMME DE FLUX (JSON → Services → Dashboard)
-------------------------------------------

generate_local_data (service HA)
        │
        ▼
capteurs_power.json
        │
        ▼
selected_sensors.json (service select_sensors)
        │
        ▼
generate_lovelace_custom (service HA)
        │
        ├──> Cartes par intégration
        │       └──> Cartes par pièce
        │               └──> Capteurs power sélectionnés
        │
        └──> Comparaison avec capteur global atom
                └──> sensor.conso_non_mesuree
        │
        ▼
Dashboard Lovelace final
        └──> Visualisation consommation & coût par pièce / intégration

===========================================
FICHIERS PRINCIPAUX IMPLIQUÉS
-------------------------------------------
- detect_local.py → collecte des capteurs
- generator.py → génération YAML / Lovelace
- config_flow.py → hub, type contrat, auto_generate
- options_flow.py → modification des paramètres et prix
- selected_sensors.json → sélection manuelle
- capteurs_power.json → capteurs détectés
- capteurs_non_mesures.json → capteurs manquants / incohérences
