===========================================
ANALYSE DU BLOQUAGE

Problème principal :
- HA ne sert pas le dossier panel_static correctement pour l'iframe
- async_register_static_paths et async_register_built_in_panel utilisés mais l’URL /home_suivi_elec/panel.html ou panel.js renvoie 404
- Utilisation d'iframe avec /panel.js n’est pas standard → HA attend généralement un URL accessible via /local/ ou /frontend_static/

Constats :
- Pas besoin d’auto_generate_lovelace pour accéder au panneau
- Fichier HTML créé automatiquement mais HA ne le sert pas correctement
- Comparaison avec un panel fonctionnel (ex. VSCode add-on) : URL en /a0d7b954_vscode/ingress, servi via frontend static intégré
- Le problème est côté **enregistrement du panneau statique** dans HA 2025.x

===========================================
PLAN DE RÉSOLUTIONS

1️⃣ Vérifier la méthode de service statique
- Remplacer async_register_static_paths + StaticPathConfig par :
  hass.http.app.router.add_static("/home_suivi_elec", panel_dir)

- Utiliser component_name="iframe", config={"url": "/local/home_suivi_elec/panel.html"} si on passe par /www
- Éviter d’utiliser panel.js directement comme URL d’iframe → HA ne le gère pas

3️⃣ Vérifier permissions et cache

4️⃣ Test

- Si affiché → iframe fonctionne
- Si toujours 404 → problème d’accès fichier / dossier / HA

5️⃣ Stabiliser code __init__.py
